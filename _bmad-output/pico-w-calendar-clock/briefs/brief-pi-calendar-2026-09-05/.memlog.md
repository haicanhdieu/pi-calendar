- (decision) MicroPython over C/Pico SDK: calendar math runs identically under CPython on a laptop, so the highest-risk logic gets automated tests for free; revisit if Phase 5 solar-term math is too slow or too large.
- (decision) Wi-Fi NTP moved from Phase 6 into v1: without it the device cold-boots to 2021-01-01, making the handoff doc's own acceptance criterion ('date and weekday are correct') unreachable by Phases 1-4.
- (decision) DS3231 stays deferred to Phase 6; its job is retention across power loss, not initial accuracy, which NTP covers.
- (decision) One push button in v1 (GPIO to GND, internal pull-up). 10s/10s auto-rotate shows a calendar on ~half of all glances, failing the device's primary job. Fallback if no button: clock-dominant rotation ~50s/8s.
- (change) Scope reordered around the Vietnamese lunar calendar as the reason the project exists: Phases 1-4 are the platform it lands on. Lunar stays deferred as a feature but binding as an architectural constraint.
- (assumption) Display controller assumed ILI9341 by main.py but never probed on the physical module. Open question; probe the ID register before finalising the driver.
- (assumption) Screen orientation unresolved: handoff doc specifies portrait 240x320 and draws both mockups that way; main.py sets 320x240 with hardcoded MADCTL 0xA8 (landscape). Blocks layout acceptance criteria.
- (event) Brief and addendum drafted from docs/pico_w_calendar_clock_handoff.md plus a bmad-party-mode round; three blocking decisions taken by Minh during that session.
- (change) Addendum gained two sections absorbed out of AGENTS.md: code conventions following from the MicroPython decision (no machine/network in pure logic, uv run pytest) and device deployment via mpremote. Per Minh's rule that AGENTS.md carries agent rules only, never tech content.
