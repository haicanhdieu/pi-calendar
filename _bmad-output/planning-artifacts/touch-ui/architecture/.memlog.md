- (constraint) Inherited from core clock spine (AD-1): src/calendar, src/time pure modules, and view-state logic stay device-import-free; hardware imports confined to src/device and main.py.
- (constraint) Inherited from core clock spine (AD-2): App remains the sole writer of AppState; new touch/bar/settings state must be committed only by App's single-threaded loop, not by an interrupt or adapter.
- (constraint) Inherited from core clock spine (AD-5): all new deadlines (bar reveal, idle timeout, press-flash) use ticks_ms/ticks_add/ticks_diff, durations from src/config.py.
- (constraint) Inherited from core clock spine (AD-7): bounded-memory rendering — no full 320x240x16 framebuffer; bar slide and settings full-screen draws must use bounded dirty-region/reusable-buffer technique like existing renderers.
- (constraint) Inherited from core clock spine (AD-11): Bar and Settings view rendering must use the existing DisplayPort contract (fill_rect/draw_text/measure_text, RGB565, font IDs) — no new drawing API.
- (constraint) Inherited from core clock spine (AD-12): UiCompositor remains sole overlay/status-layer owner and draw-last authority; touch UI must compose through it, not bypass it with direct display calls from App.
- (constraint) Inherited from wifi-config spine (AD-1/AD-6): NetworkCoordinator remains sole WLAN/HTTP owner; App remains sole on-screen network-status writer via NetworkEvent reduction. Touch UI reads existing App-owned overlay state (kind/ssid/ip) for the Settings view, it does not add a second path to network data.
- (decision) AD-6 override: touch-ui FR-1 fully replaces wifi-config AD-6's display clause. Network-status overlay never auto-draws in ANY NetworkCoordinator mode (Setup-AP or station) — App stops calling draw_network_status_overlay from the base-view render path entirely; the same status data (kind/ssid/ip already reduced onto App) is instead read once when Settings view opens. This amends wifi-config's ARCHITECTURE-SPINE.md AD-6, which must be updated to drop its 'continuously shows'/'at least 10 seconds' display rule (the reduction/state-holding half of AD-6 is unaffected).
- (decision) Touch input enters App via a new src/device/touch_port.py TouchPort, polled synchronously once per App.step() (mirrors ClockPort.read_utc()) — returns an immediate touch/no-touch result, no queue/coordinator/mailbox. Justified: XPT2046 SPI read is a bounded non-blocking transaction, unlike WLAN/HTTP which need cooperative ticking.
- (decision) SPI0 bus arbitration: TouchPort exclusively owns the TFT/touch CS handoff (deselect tft_cs, select touch_cs, transfer, deselect touch_cs, reselect tft_cs) around its own read. Ili9341DisplayPort stays unaware a touch peripheral exists and never touches touch_cs. Prevents two adapters independently racing to drive shared SPI0.
- (decision) Reboot crosses the hardware boundary via a new src/device/reboot_port.py RebootPort with a single reset() method, matching the existing ClockPort/DisplayPort convention. main.py backs it with machine.reset(); host tests inject a fake that records the call instead of executing it.
- (decision) Touch/Bar/Settings state machine is a new pure module src/ui/touch_state.py mirroring view_state.py's shape (pure functions over an explicit state value, no device imports) — not ad hoc logic inside App methods. New AppState fields (active_surface: rotation|bar|settings, surface_deadline) are added to the existing single AppState object; App remains sole committer (AD-2).
- (decision) Bar/Settings suppress Rotation's own step 4 view-deadline handling entirely while active (not merely extend it): App.step() only evaluates next_view_after_dwell when active_surface == rotation. On return to rotation (timeout or outside-tap), the currently active Clock/Calendar view's dwell timer is freshly re-armed from now, realizing the UX spec's 'resumes from the view it was showing' without needing to persist elapsed dwell time.
- (decision) Bar slide (200-300ms) renders as several incremental fill_rect steps of the bar strip's y-position, driven by a tighter animation sub-tick distinct from CLOCK_REDRAW_MS, using the existing bounded dirty-region/reusable-buffer technique (AD-7) — no full-frame buffer. Actual frame count/pacing and whether the ILI9341 fill rate holds it without stutter is Deferred to on-device profiling, per the PRD's own flagged NFR assumption.
- (decision) Idle timeout is a single named config.py constant (TOUCH_IDLE_TIMEOUT_MS = 15000), shared by Bar-Revealed and Settings, per the UX spec's locked Discovery decision (overrides PRD's stated 5-8s range).
- (decision) Bar is a compositor-drawn overlay component (new src/ui/components.py draw_bar / bar_rect helpers, or a small src/ui/bar_view.py), drawn after the frozen base view and its own press-flash, analogous to how the UNSYNCED badge already draws last — it does not become a fourth AppState active_view. Settings, by contrast, IS a third full-screen active_view value (alongside VIEW_CLOCK/VIEW_CALENDAR) rendered through the same compositor.render() path as Clock/Calendar, since it suspends Rotation entirely and nothing draws underneath it.
- (question) Does the UNSYNCED badge still draw during Settings (which already shows the true network state explicitly), or is it suppressed while Settings is the active view? Neither PRD nor UX spec says. Deferred — default to current AD-12 behavior (badge draws whenever trust==unsynced, regardless of active view) unless the user says otherwise, since no source calls for a special case.
- (question) Touch debounce / palm-rejection: PRD §8 flags this as an owner-less open risk, not designed here. This spine does not add a debounce invariant; TouchPort returns raw touch/no-touch per read. Revisit before shipping if false Bar-reveals prove real on hardware.
