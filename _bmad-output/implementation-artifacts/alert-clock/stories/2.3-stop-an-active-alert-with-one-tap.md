<intent-contract>

## Intent

**Problem:** Active alerts currently ignore touch input, forcing the owner to wait five minutes for Auto-stop.

**Approach:** Reserve touch handling while an occurrence is active, recognize one debounced edge in the middle STOP band, and resolve the occurrence before the buzzer tick for that loop pass.

## Boundaries & Constraints

**Always:** Keep active-alert touch handling exclusive; silence before returning to Rotation; rearm the last normal view dwell; preserve repeating alerts; disable one-time alerts only when their ids still exist in canonical settings; leave pure code free of hardware imports.

**Never:** Add Postpone behavior, change scheduler timing, delete alerts, force Clock view, or claim Pico hardware validation from host tests.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|---|---|---|---|
| Stop | Active occurrence and edge inside middle 50% screen band | Silence, resolve all members, resume prior normal view | No buzzer tick after terminal transition |
| Bounce/replay | Further edge before release or after resolution | No second action or normal-surface navigation | Consume until release |
| One-time member changed | Active one-time id missing from current canonical settings | Resolve without recreating or failing occurrence | Keep current settings |

</intent-contract>

## Code Map

- `src/app.py` -- polls one touch sample per loop and owns normal-surface transitions; active alerts must intercept samples before Bar/Settings logic.
- `src/alert/runtime.py` -- owns active occurrence transitions and currently auto-stops before buzzer tick.
- `src/alert/terminal.py` -- shared canonical one-time disable behavior for terminal resolution.
- `src/ui/alert_view.py` -- defines 25/50/25 alert geometry and STOP label.
- `tests/test_alert_app.py` -- existing App alert fakes and lifecycle tests; add stop, ordering, repeat, one-time, and debounce coverage.

## Tasks & Acceptance

**Execution:**
- `src/app.py` -- route active-alert touch edges exclusively and latch until release -- prevent normal navigation and replayed taps.
- `src/ui/alert_view.py` -- expose pure STOP hit geometry -- keep screen layout as source of truth.
- `src/alert/runtime.py` -- resolve requested Stop before `BuzzerPort.tick`, silence, terminal-process members, clear active state, and rearm dwell.
- `tests/test_alert_app.py` -- cover Stop lifecycle, ordering, repeating preservation, one-time canonical disable, and debounce.
- `_bmad-output/implementation-artifacts/alert-clock/stories/2.3-stop-an-active-alert-with-one-tap.md` -- record verification and final status.

**Acceptance Criteria:**
- Given an active occurrence, when a valid debounced touch lands in the middle 50% STOP band, then the buzzer is silenced and normal Rotation resumes at the last normal view with dwell rearmed.
- Given App processes Stop, when that loop pass executes, then Stop resolves before the single buzzer tick and no cadence reasserts after silence.
- Given a repeating base alert, when Stop resolves it, then it remains enabled and stored.
- Given a one-time base alert, when Stop resolves it, then current canonical settings are reread and only an existing matching id is disabled.
- Given bounce or replayed edges before release, when App loops, then no second resolution or normal-surface navigation occurs.

## Design Notes

The physical touch adapter already emits one edge per contact. App adds an alert-owned release latch because a replayed edge can arrive after the occurrence has ended and must not open the normal Bar surface.
