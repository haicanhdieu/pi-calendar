## Intent

**Problem:** Host tests cannot prove audible output, touch behavior, display legibility, reboot persistence, or Wi-Fi-unavailable operation on Pico hardware.

**Approach:** Flash stock MicroPython 1.29.0 plus alert feature, execute one evidence run on physical Device, and record host and device evidence separately under `test-artifacts/alert-clock/`.

## Boundaries & Constraints

**Always:** Record each device result with firmware identity, serial checkpoints, observed timestamps, and artifact path. Keep host pytest results separate. Report unavailable hardware as unverified.

**Never:** Do not infer hardware behavior from host tests, do not claim flashing or observation without physical evidence, and do not change alert implementation while performing validation.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|---|---|---|---|
| Full alert | Configured alert reaches due minute | Buzzer cadence and alert screen captured | Mark unverified if Device unavailable |
| Controls | Active alert; STOP or POSTPONE tapped | Silence, normal rotation/deferred due time, and later re-alert recorded | Preserve serial evidence on failure |
| Auto-stop | Unanswered active alert for five minutes | Return to normal rotation recorded | Record timeout and terminal state |
| Collision | Two alerts due same minute | One combined occurrence and one resolution recorded | Record count and IDs without secrets |
| Persistence | Pending postpone; reboot before/after due time | Future occurrence restores; overdue occurrence skips | Record power-cycle evidence separately |
| Offline | Wi-Fi unavailable at due minute | Local-time alert sounds and `UNSYNCED` appears | Record retained-time state |
| Non-blocking | Sounding alert while Config page requested | Web responds and clock advances | Record any bounded failure code |

</intent-contract>

## Code Map

- `src/alert/` -- alert scheduling, occurrence, collision, postpone, and resolution behavior under device validation.
- `src/app.py` -- cooperative loop and control/evaluation ordering.
- `src/device/buzzer_port.py` -- 180 ms high / 220 ms low buzzer cadence.
- `src/ui/alert_view.py` -- active alert labels, controls, deferred time, and `UNSYNCED` badge.
- `_bmad-output/test-artifacts/alert-clock/` -- destination for separate flashed-device evidence.
- `tests/` -- host-only evidence; cannot substitute for physical Device observations.

## Tasks & Acceptance

**Execution:**
- `_bmad-output/test-artifacts/alert-clock/` -- add host-evidence and device-evidence records as separate artifacts -- preserve provenance and prevent unsupported hardware claims.
- `docs/` -- no changes unless physical wiring or measured electrical behavior is observed -- avoid altering hardware source of truth from assumptions.

**Acceptance Criteria:**
- Given stock MicroPython 1.29.0 and flashed alert firmware, when the evidence run executes, then every result is filed under `test-artifacts/alert-clock/` separately from host pytest output.
- Given a configured due alert, when it fires, then cadence, screen, touch calibration, STOP, POSTPONE, auto-stop, collision, reboot persistence, Wi-Fi-off operation, and non-blocking web behavior are each evidenced or explicitly marked unverified.
- Given no physical Device access, when validation is attempted, then no hardware behavior is claimed and the blocker is recorded with required next steps.

## Design Notes

Device evidence is observational and cannot be generated by CPython tests. Required evidence includes serial capture, screen photographs, touch outcomes, power-cycle observations, and browser response observations. Host pytest remains supporting evidence only.
